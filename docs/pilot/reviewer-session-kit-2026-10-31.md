# Guided reviewer session kit — 31 October 2026

**Prepared only: no invitations, consent, sessions, timings or ratings are recorded.** The owner arranges participation by one to three peers. This kit makes the existing [reviewer protocol](reviewer-protocol.md) concrete without exposing reserved qualification questions.

## Task cards and source access

Use these two **consumed development** tasks, not the reserved v4 set:

| Task | Question |
|---|---|
| r03 | For Thailand in December 2024, what drove the monthly headline-inflation increase, and why did core inflation stay stable? |
| r04 | How did Thai private investment compare month-on-month in December 2024 and quarter-on-quarter in the fourth quarter, and which categories explain those directions? |

Both use the pinned BOT December/quarterly release published on 31 January 2025. Give the same source access in both conditions. A local packet under `reports/workflow_pilot/production-readiness-2026-10-27/resume-v39/reviewer-kit/` provides the questions, normalized source units, optional saved drafts and hash provenance. It contains no Ragas scores or prior owner ratings. The full publisher snapshot remains pinned locally; normalize/extraction provenance is explicit.

Do not use r07–r22 or r27–r30 for practice, demonstrations or tuning before qualification. Earlier unused r23–r26 remain archived, not a substitute demonstration pool. Common source documents are not independent evidence and these practice tasks cannot establish fresh model quality.

## Facilitator sequence

1. Explain the supervised portfolio-pilot limits. Obtain permission for anonymized notes, assign an alias, and leave unknown measurements blank. Do not collect customer or sensitive personal data. Consent is not approval of a draft or permission for model generation.
2. For the first reviewer, use r03 manually and r04 assisted; reverse task/mode order for the next reviewer when feasible. These tasks differ in content and complexity, so this tiny comparison cannot establish causal time savings. Do not give a draft, reference answer or owner judgment before the manual task finishes.
3. For the manual task, start timing when the question and source are supplied. Stop when the participant has prepared and checked a short final brief. Record source-checking and editing time as part of the total.
4. For an assisted-live task, first obtain a separate generation allowance and confirm application/model/corpus identity. Preserve the raw output before edits. Record waiting, checking, correction and final-decision time, plus failures and incomplete tasks. Do not reset the clock or retry invisibly.
5. If no generation allowance is available, an optional saved-draft inspection can be used for source-review/usability feedback. Label mode `assisted-frozen`. Its time measures inspection/correction only; it is not live generation latency or an end-to-end assisted task. Historical drafts are unchanged and not newly generated by v1.55.
6. Record findings in a **new copy** of the existing [session template](reviewer-session-template.csv), not the completed owner `human_review.csv`. Consent, mode, task, aliases, identities, raw time, corrections, usefulness and incomplete outcomes must reflect actual events. Record pre-session knowledge and deviations in notes.
7. If using the application, the participant must inspect and approve/reject the exact stored revision. An edited brief needs a new revision and approval. A spreadsheet entry, saved draft card or facilitator opinion is not application approval. Empty claims remain unexportable.

The application review payload supports review notes, task/manual seconds and usefulness, but it does not replace the session record's consent, assigned mode, task ordering and protocol deviations. A manual task without an application run has no run/revision ID; leave those fields blank.

## Feedback and completion evidence

Ask whether each requested component was covered, whether citations support the claims, what required correction, and whether warnings helped. Ask what would prevent using the workflow again. Record the participant's words and any task abandonment without supplying a desired rating.

After real sessions, report participant/task counts, modes, raw observations and missing data. Identify one feedback-supported improvement and repeat the affected checks. Preserve the original session evidence and raw outputs. A saved-draft review alone cannot satisfy the complete live-workflow usage gate or establish ROI, production readiness or independent model-quality scores.

**Manual human work remains required:** the owner arranges invitations and operating consent; real reviewers perform tasks and judge support/usefulness; exact stored drafts require human approval before export. No invitation, model call, review decision or export is performed by preparing this kit.
