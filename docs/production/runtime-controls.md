# Local runtime admission boundary

The single-instance analyst API admits at most **two queued tasks**, enforced in the same SQLite write transaction as task creation or explicit retry. The default application now owns one child process at a time. Before it claims the first task, the queue still cannot exceed two; a third request can be accepted after one queued task becomes active. This is a capacity limit, not a promise of a queue position or completion time.

At capacity, a new request receives HTTP **429** with `Retry-After: 5` and no task/history row is created. The header suggests when to try; it does not initiate automatic retries or guarantee capacity five seconds later. Existing matching request keys still return the original task without consuming another slot. Reusing a key with different input still conflicts. A rejected retry leaves its interrupted/failed task unchanged. No SQLite schema, request/response success shape, review rule or dependency version changes.

Offline tests race twenty admissions against a two-slot queue, exercise retry rollback and duplicate keys, and use a blocking synthetic engine to verify one active/two queued tasks plus HTTP rejection of excess work. They make no model calls. The optional store-level limit defaults to the previous unrestricted behavior for existing direct callers; the analyst API explicitly configures two. Do not infer admission controls for the legacy graph or other store clients.

This qualification scope supports **one application process/instance**. An OS runtime lease rejects a second owner before startup recovery can modify the database. The launcher supplies one Uvicorn worker; this lease is not a distributed database/queue design. Do not increase workers/replicas without a separate runtime design and fault tests.

## Owned process deadline and cancellation

The normal factory/launcher uses an owned spawned process with a **180-second monotonic execution deadline**, including imports, generation, NeMo and process cleanup. The parent kills/reaps its own worker on timeout/cancellation; a child watchdog also monitors its owner and deadline. A candidate draft is accepted only after clean process exit and a current-attempt/corpus check. The database remains the authoritative queue; waking the dispatcher does not accumulate an unbounded in-memory task list.

An additive authenticated `POST /api/runs/{id}/cancel` and browser button interrupt queued/running tasks. Exact attempt identifiers in the existing event history fence late events/results after cancellation or retry. No schema migration or automatic retry/approval is introduced. Completed/approved drafts cannot be canceled into a retryable state. Failure metrics preserve known tokens and mark in-flight/internal usage and monetary cost as unknown.

Injected custom test engines and explicit inline tests retain their existing controlled execution path for compatibility; they do not receive a production deadline claim, and the process cancellation API rejects that mode. HTTP clients cannot select an injected engine. The actual default-process path was exercised with an out-of-scope request and unreachable model URL: it returned an empty unapprovable draft with zero model/policy calls.

Spawned synthetic tests cover model/guard hangs, candidate-before-crash/hang, malformed/oversized messages, post-result events, cancellation, explicit retry, changed corpora, shutdown, second-owner rejection and approval/export lifecycle. A separate disposable-parent test verified that the monitored synthetic child exits when its owner is killed. A Windows pipe-close edge case initially failed normal results; the retained diagnostic identified `BrokenPipeError` from `poll()`, and closure is now handled separately from malformed messages.

On Windows the watchdog requests only synchronization access to its owner and checks the process handle without waiting; this avoids PID-based signal probes. See Microsoft's [OpenProcess](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-openprocess) and [WaitForSingleObject](https://learn.microsoft.com/en-us/windows/win32/api/synchapi/nf-synchapi-waitforsingleobject) contracts.

Queue wait is measured separately. The IPC boundary caps a message at 1 MiB and an attempt at 128 messages. Kernel scheduling/termination acknowledgement adds cleanup overhead; this is not a hard real-time operating-system guarantee. Killing a client does not prove an inference server immediately stopped computing, so actual backend cancellation remains a live qualification gate. Queue expiry, sustained saturation, deployment faults, alert delivery and multi-user identity remain unfinished. These controls do not complete production readiness.
