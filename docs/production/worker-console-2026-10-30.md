# Isolate worker console output from application logs

The real worker entrypoint, exercised in an isolated native process with a synthetic engine, sent only an exception class through its failure channel. A dependency logger and a direct stderr print nevertheless exposed their synthetic private text through the inherited console. This confirms an output-channel gap; no actual credential disclosure or model inference was used to establish it.

The worker now redirects stdout/stderr OS descriptors to the null device before dependency imports. On Windows it also replaces the process standard handles, covering native `WriteFile` calls that could bypass Python logging. Redirected descriptors remain open even when opening the null device reuses a previously closed console slot. Isolation failure stops the attempt before importing the engine. The owner process's console is not redirected.

This intentionally suppresses raw worker console output. Structured tool events, result and typed failure messages continue through the existing IPC channel; the parent retains its existing failure/exit/deadline telemetry and never approves or retries automatically. Request schemas, prompts, model settings, retrieval, database schema, output artifacts and dependencies are unchanged. Historical logs/evaluation evidence are not rewritten. This worker-only helper must not be called in the owner process.

Native subprocess fixtures verify Python logging/prints, `os.write`, Windows standard-handle writes and initially closed console descriptors. All console output is absent while exit 1 and the exact `RuntimeError` failure message survive. Two privacy cases pass; the broader targeted runtime set passes 17 checks. Full offline and container validation is retained separately in ignored `reports/workflow_pilot/production-readiness-2026-10-27/resume-v21/`; consult its final/progress record before treating this as fully integrated.

Console isolation does not cover a library deliberately opening another file or network destination, the separate model service, proxies or host logs. The worker is not a general sandbox. Diagnose failures through safe IPC metadata and synthetic reproduction rather than restoring raw provider text to shared logs. Broader permissions, retention, incident ownership and alert delivery still require target-specific qualification.
